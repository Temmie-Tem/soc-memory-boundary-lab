# SDM855 Memory Boundary Lab

[English](README.md) · **한국어**

> 이 문서는 **개요**입니다. 실험별 결과와 증거 사슬 전문은 영문
> [`README.md`](README.md)와 [`STATUS.md`](STATUS.md)에 있습니다. 두 문서가
> 어긋나면 영문이 정본입니다.

Samsung SM-A908N / Qualcomm SM8150에서 **최종 system-physical-address와 DRAM
사이의 매핑**을 증거 기반으로 연구합니다.

중심 질문은 하나입니다. **Normal World의 물리 주소가 한 보호 계층에서 통과
판정을 받은 뒤, 나중에 다른 보호 대상 DRAM 목적지로 변환될 수 있는가?**
이 저장소는 AMD Skitter Creek 결과가 퀄컴에도 적용된다고 **가정하지 않습니다.**

## 이 저장소는 익스플로잇이 아닙니다

공개 시점 분류는 `CLASS C (TRANSFORM ONLY)` / `NOT_ELIGIBLE`입니다. 구체적으로:

- alias나 보호 우회는 **관측되지 않았습니다.**
- DDR/controller, XPU, SMMU, SCM, EL2, EL3, protected-memory에 대한 **쓰기를
  수행한 적이 없습니다.**
- 연구 대상 기기는 **저자 본인 소유**입니다.

지금까지 얻은 것은 구조 매핑과 미결 결론이지 동작하는 공격이 아닙니다. 만약
이후에 실제 격리 우회가 성립하면 공개 글보다 **벤더 조율 공개를 먼저** 거칩니다.
그 방침은 [`SECURITY.md`](SECURITY.md)에 미리 적어두었습니다.

## 주장 라벨 다섯 개

이 저장소를 읽을 때 가장 중요한 부분입니다. 모든 사실과 결론에 아래 라벨 중
하나가 붙으며, **라벨은 적힌 것 이상으로 읽으면 안 됩니다.**

| 라벨 | 뜻 |
| --- | --- |
| `PROVED` | 명시된 소스·산출물·반복 결과로 직접 입증됨 |
| `SUPPORTED` | 여러 관측이 뒷받침하지만 결정적 연결이 빠져 있음 |
| `HYPOTHESIS` | 예측을 명시한 반증 가능한 설명 |
| `UNKNOWN` | 현재 증거가 불충분함 |
| `REFUTED` | 명시된 증거가 주장을 반박함 |

`REFUTED`는 **그 모델·범위·조건 안에서의 부정**이지 전역 부재를 뜻하지
않습니다. 마찬가지로 `UNKNOWN`은 "없다"가 아니라 "아직 측정·복원·검증되지
않았다"입니다.

주장을 한 단계 **낮추는** 정정은 새 결과와 같은 값어치를 가지며 부끄러운 일로
취급하지 않습니다. 기여 규칙은 [`CONTRIBUTING.md`](CONTRIBUTING.md)에 있습니다.

## 공개하는 것과 하지 않는 것

**공개합니다** — 디코딩된 레지스터 맵, 주소 관계, 권한 워드 해석, 그리고 각
발견을 그 입력에 해시로 결박하는 매니페스트. 이것들은 이 프로젝트의 산물입니다.

**공개하지 않습니다** — 그 분석이 유래한 펌웨어. 원본 이미지, 추출 바이너리,
raw 기기 출력은 `evidence/private/` 아래와 `.gitignore` 확장자 규칙으로 공개
트리 밖에 둡니다. 매니페스트가 입력을 해시로 지칭하는 것은 **결박 기록이지 그
입력의 배포가 아닙니다.**

퀄컴·삼성 펌웨어(XBL, TrustZone, QHEE, devcfg 등)는 MIT 허가 범위 밖입니다.
자세한 경계는 [`NOTICE`](NOTICE)를 참고하십시오.

## 상위 프로젝트

이 저장소는 [**android-native-init-lab**](https://github.com/Temmie-Tem/android-native-init-lab)에서
파생됐습니다. 관측에 쓰는 플랫폼 전체 — A90 네이티브 런타임, ACM bridge, REPL —
과 기기 안전 계약이 그쪽에서 옵니다. 어느 쪽에서 무엇이 오는지는 영문 README의
`Upstream` 절에 정확히 나눠 적혀 있습니다.

**이 저장소는 어떤 기기 권한도 부여하지 않습니다.** 상위 프로젝트의 `AGENTS.md`
안전 계약을 무효화하는 절차도 없습니다. 여기 기술된 작업은 잘못 수행하면 기기를
부팅 불가 상태로 만들 수 있습니다.
